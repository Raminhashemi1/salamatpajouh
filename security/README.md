# سلامت‌پژوه — کنترل فنی در اختیار مالک (پیشنویس غیرعملیاتی)

**وضعیت: صرفاً طراحی و هستهٔ آزمون‌پذیر مجوزها در شاخهٔ توسعه.**
هیچ پنل ورود، احراز هویت سروری، پایگاه داده، انتشار محتوا یا حساب شریک در سایت عمومی ساخته/فعال نشده است.
به شاخهٔ اصلی `main` دست نزنید تا سرور امن، احراز هویت و بازبینی امنیتی کامل شود.

## نقش‌ها
- **مالک / owner:** بازبینی و انتشار محتوا، مدیریت حساب‌ها و نقش‌ها، تنظیمات مالی و نسبت‌های تقسیم درآمد، کلیدهای عملیاتی و انتشار نسخه.
- **تأمین‌کننده محتوا / content_editor:** ساخت پیش‌نویس، ویرایش/مشاهده/ارسال پیش‌نویس‌های خودش برای بررسی. بدون انتشار مستقیم، تغییر کد، تغییر درگاه، تغییر سهم‌ها یا دسترسی به اطلاعات کاربران.
- **گزارش مالی شریک:** فقط سند *تأییدشده، نهایی‌شده و متعلق به همان شریک*؛ بدون اختیار تغییر پرداخت‌ها.

## الزامات پیاده‌سازی واقعی
1. نقش و شناسه کاربر فقط از جلسهٔ **احراز هویت‌شده در سمت سرور** خوانده شود؛ درخواست HTTP نباید بتواند نقش را تعیین کند.
2. هر endpoint حتی APIهای مخفی/موبایل باید `requirePermission` را با دادهٔ منابعِ خوانده‌شده از پایگاه داده اجرا کند؛ فیلتر `authorUserId` در خود query الزامی است.
3. چرخهٔ محتوا: پیش‌نویس → ارسال برای بازبینی → تأیید مالک → انتشار. برگشت/رد محتوا همراه با تاریخ و دلیل ثبت شود.
4. تغییر حساب‌های مالی، نسبت تقسیم درآمد، تأیید هزینه و انتشار نسخه فقط با مجوز مالک و ترجیحاً ورود مجدد/عامل دوم؛ ثبت گزارش تغییرات غیرقابل ویرایش.
5. قطع دسترسی شریک با غیرفعال‌کردن حساب و ابطال نشست‌های فعال؛ مطالب منتشرشده و پشتیبان‌ها محفوظ.
6. حساب‌ها و دسترسی‌ها در سرویس امن HTTPS و دیتابیس با پشتیبان‌گیری منظم؛ هیچ کلید یا رمز حساب بانکی در مخزن عمومی/کد فرانت‌اند ذخیره نشود.
7. تست‌های نفوذ و کنترل دسترسی، CSRF، محدودیت درخواست، جلوگیری از XSS در محتوای قابل‌انتشار و ممیزی تغییرات قبل از بهره‌برداری ضروری‌اند.

## اجرای آزمون
`node --test security/access-policy.test.mjs`

## کنترل حساب و مخزن
- مخزن فعلی **عمومی** است: مطالعهٔ کد از سوی افراد دیگر با مجوز نوشتن متفاوت است.
- شاخهٔ `main` بر اساس آخرین بررسی هنوز حفاظت نشده بود. حفاظت شاخه را از GitHub → Repository Settings → Branches / Rules (طبق UI) فعال کنید: منع force push و deletion، الزام PR و ترجیحاً CI. برای دریافت تأیید بازبین مستقل پیش از ادغام برنامه‌ریزی شود.
- ورود دومرحله‌ای GitHub فقط توسط خود مالک از Settings → Password and authentication انجام شود؛ کدهای بازیابی را امن نگه دارید.
- سرویس‌های دامنه، هاست، DNS، GitHub Pages/استقرار، بانک، درگاه و پشتیبان‌ها باید با حساب‌های تحت کنترل مالک باشند.
- اتصال موجودِ ChatGPT Codex Connector را هنگام نیاز به حداقل سطح دسترسی بازبینی کنید.
- **این بسته مجوزهای واقعی GitHub یا انتشار سایت را تغییر نمی‌دهد**؛ از شریک نیز هنوز هیچ حسابی ساخته نشده است.
